# sec-webhook-sign

## 题面

支付回调的签名校验上线后，重放昨天的报文依然能改掉订单状态：规范化签名串按字典插入顺序拼接字段，字段顺序一变签名就变，验签结果随请求头顺序漂移；规范化签名串不含请求体，请求体被篡改后签名依旧可以通过；签名比较使用普通等号而非恒定时间比较，比较耗时泄漏签名前缀；验签前先解析 JSON，解析阶段就可能触发危险逻辑；时间窗只比较时间戳差的绝对值，未来时间戳同样放行；时间窗窗口从配置读取后被写死成一天，配置形同虚设；重放检测只登记随机串不查询，同一个随机串可以反复使用；重放存储从不清理过期项，长时间运行内存无界增长；策略校验不检查签名算法强度，弱算法也能通过；批量校验复用重放存储与规范化串，后一个请求会命中前一个请求的结果。hook/verify.py 是核心，tests/unit/test_verify.py 15个红，另一个边界目录另有 5 条。要修的是：按上面的顺序把 10 个缺陷逐个修掉。

## 运行方式

在仓库根目录执行：

```bash
python -m pytest tests -q
```

当前 hook/verify.py 的 8 个函数全部是 raise NotImplementedError 的桩，因此 15 条测试全部失败，预期结果恰好为 15 failed、0 error：

```text
15 failed
```

## 测试布局

本仓库采用测试拆分布局，合计 15 条测试：

- tests/unit/test_verify.py：10 条契约测试，每条对应题面中的一个缺陷；
- tests/behaviour/test_verify_edge.py：5 条边界测试，覆盖合法请求全部通过、篡改请求体被拒、过期时间戳被拒、同一随机串第二次被拒、两批独立校验与单独校验相同。

tests 目录不可修改，修改测试视为无效提交。所有测试只依赖 Python 标准库与 pytest，离线运行，时间通过参数显式传入，不使用随机数。

## 修复要求

hook/verify.py 是唯一实现文件，恰好 8 个函数桩。按题面顺序把 10 个缺陷逐个修掉，并保持 tests 不变。
